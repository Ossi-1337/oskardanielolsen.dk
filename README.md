# oskardanielolsen.dk

oskardanielolsen.dk is a portfolio website for displaying projects and profile
links.

The site uses plain HTML, CSS, and JavaScript with no runtime dependencies.

## Asset versions

Run `node scripts/version-assets.mjs` after changing CSS, JavaScript, or contact
icons. It adds content hashes to their URLs (`?v=…`) and changes only the versions
whose content changed. Run `node scripts/version-assets.mjs --check` to verify
that committed versions are current.

In Cloudflare Pages, set the build command to `node scripts/version-assets.mjs`
and keep the build output directory as `public`. This generates versions on
every deployment without installing dependencies. The currently configured
`exit 0` command still serves the committed versions, but does not update them
automatically; change it after the script is available in the remote repository.

HTML is not cached, so each response receives a fresh CSP nonce. CSS, JavaScript,
and versioned contact icons can stay in the browser cache for one day. A normal
visit or reload picks up deployed updates without a hard refresh; an already
open page does not update itself.

## Content Security Policy

`functions/_middleware.js` generates a cryptographically random 256-bit nonce
for every HTML response, including Pages' HTML fallback routes. Cloudflare reads
the nonce from the CSP response header and attaches it to its injected
[JavaScript Detections scripts](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/#if-you-have-a-content-security-policy-csp).
The site's external script remains allowed by `'self'`. Arbitrary inline scripts,
inline event handlers, and third-party scripts remain blocked; there is no
`unsafe-inline`, `unsafe-eval`, fixed nonce, or static script hash allowance.

HTML uses `no-store` for browsers and CDNs. The middleware strips conditional and
range request headers and removes HTML validators so an older body cannot be
combined with a fresh CSP nonce. It sets CSP and Permissions Policy itself,
because `_headers` rules are not applied to responses generated by Functions.
The strict static CSP remains as a fallback.

`public/_routes.json` invokes Functions for HTML and API requests and excludes
each existing static asset by its exact path. Keep that list current when adding
assets. Avoid directory-wide exclusions: a missing asset can return Pages' HTML
fallback, which also needs a nonce. HTML requests now count toward Pages
Functions usage; the excluded assets keep their static serving and caching.

After deploying through the normal repository workflow, use Pages **Settings >
Runtime > Fail open / closed** to select **Fail closed** if it is not already set.
This prevents the platform from bypassing nonce generation if the Functions
allowance is exhausted. Keep HTML out of any dashboard Cache Everything or
Edge Cache TTL override that ignores the response's `no-store` headers.

Verify on the deployed custom domain that two HTML requests have different
`'nonce-…'` values, injected Cloudflare scripts carry the matching nonce, and
unapproved inline scripts remain blocked. Local development cannot reproduce
Cloudflare's edge injection. Browser extensions may still produce CSP errors
when attempting to inject scripts; do not allow those scripts just to hide errors.
